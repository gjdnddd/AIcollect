# Hermes 활용 가이드

> Hermes 에이전트 전용 슬래시(/) 명령어.
> 멀티 에이전트 자동화 툴 Hermes를 일상 업무·연구·개인 지식 관리(PKM)에 활용하기 위한 핵심 명령어.

---

## ① 상태 · 모델 제어

> **사용 시점: Hermes 세션 시작 시 / 세션 상태 파악이 필요할 때**

- **`/status`** — 현재 세션 ID, 대화 타이틀, 토큰 사용량 등 상태 요약 확인
- **`/reasoning [low / medium / high / xhigh]`** — AI의 사고 깊이(추론 단계) 조정. 복잡하고 정교한 로직엔 `high`·`xhigh`
- **`/model [모델명]`** — 실시간으로 최적의 LLM 엔진 교체
- **`/raw`** — 매 작업마다 요구되는 수동 승인(Approval) 절차를 생략, 중단 없이 실행하는 로우 모드
- **`/footer`** — 화면 하단에 실시간 토큰 소모량·모델 정보 인디케이터 토글
- **`/help`** — 지원하는 전체 명령어 가이드 호출

---

## ② 세션 · 컨텍스트 관리

> **사용 시점: 세션이 길어질 때 / 잘못된 방향으로 흘러갈 때 / 대화를 분기해서 실험할 때**

- **`/compress`** — 컨텍스트 한계 도달 시 기존 메시지 흐름을 스마트하게 압축·요약
- **`/resume`** — 과거 대화 세션 히스토리를 시각화 호출. 특정 세션명으로 과거 흐름에 복귀
- **`/rollback [숫자]`** — 원치 않는 방향으로 흘러갔을 때 특정 체크포인트로 즉시 되돌리기
- **`/branch`** — 기존 타임라인을 보존한 채 `Case A`·`Case B` 실험 분기를 만들어 병렬 테스트

---

## ③ 리서치 · 지식 관리 (PKM)

> **사용 시점: 리서치·정보 수집 시 / 수집한 내용을 옵시디안에 저장할 때**

- **`/archive`** — 최신 학술 논문·디지털 아카이브 자원을 실시간 리서치·요약
- **`/llm_wiki`** — 인터넷 링크·리서치 결과물을 개인 위키 볼트(옵시디안 등)에 PDF 임베드 및 구조화 마크다운 노트로 자동 저장
  - 확장 팁: 스키마(Schema) 규칙에 속성을 미리 부여하면 사용자 개입 없이 AI가 지식을 연결·팽창시킨다
- **`/obsidian [검색어]`** — 로컬 PC의 옵시디안 볼트 경로를 추적해 내부 문서를 검색하고 답변 컨텍스트로 활용
- **`/workspace`** — 구글 API(크레덴셜) 연동으로 캘린더 일정 조회·이메일 추적 등 업무 비서 역할

---

## ④ 자동화 · 백그라운드

> **사용 시점: 장시간 작업 자동화 / 목표 달성까지 자율 루프 원할 때 / AI정보통합 자동 정리 시**

- **`/steer`** — AI가 답변을 출력하는 도중 즉시 개입해 실행 방향을 원하는 목적지로 전환
- **`/background`** — 장시간 소요되는 무거운 작업을 백그라운드로 돌리고 다른 작업 병행
- **`/goal [목표명]`** — 장기 목표·토큰 버짓(예: 20턴)을 설정하면 목표 달성까지 에이전트가 자율적으로 루프
- **`/update`** — 에이전트 엔진 자체를 최신 안정화 버전으로 자동 깃 풀링·업데이트
- **`/debug`** — 오류 발생 시 시스템 로그·인포메이션 리포트를 생성해 트러블슈팅 지원

---

## ⑤ 개념 · 아키텍처 개요

> **사용 시점: Hermes 도입 검토 시 / 기존 챗봇과의 차이 설명이 필요할 때**

- **정의**: 노스 리서치(Nous Research) 개발, MIT 라이선스 오픈소스 자율형 멀티 에이전트 시스템 (2025.07 출시, 깃허브 스타 19만 달성)
- **핵심 가치**: 노트북을 끄거나 자리를 비워도 VPS·도커 환경에서 24시간 상시 대기하며 독립적으로 업무 수행하는 자율형 AI 직원

### 기존 챗봇(ChatGPT·Claude·Gemini) vs Hermes

| 비교 항목 | 기존 단독 LLM | Hermes 에이전트 |
|---|---|---|
| 작동 방식 | 수동적 챗봇 — 매번 프롬프트 필요 | 능동적 에이전트 — 목표만 주면 스스로 계획·실행 |
| 지속성 | 브라우저·앱 종료 시 작업 중단 | 도커 내 24시간 상시 구동 |
| 자가 개선 | 대화 맥락은 기억하되 도구·지식 발전 없음 | 폐쇄 루프 학습 — 문제 해결법을 `skill.md`로 자동 축적 |
| 인프라 제어 | 로컬 PC 제어·백그라운드 파일 수정 불가 | 샌드박스(도커) 내 터미널·파일·브라우저 제어 |
| 외부 연동 | 내부 플러그인 의존, 메신저·크론잡 제한적 | 디스코드·텔레그램·슬랙 연동, 크론잡 자동 브리핑·이슈 자동 해결 |

### 4대 핵심 마크다운 파일 (컨텍스트 엔지니어링)

초기 구축 시 사용자와 딥 인터뷰로 이 파일들을 견고히 세팅하면 효율 극대화.

1. **`soul.md`** — 에이전트 정체성·성격·핵심 규칙
2. **`agents.md`** — 업무 프로세스·코딩 규칙·금지 사항 프로토콜
3. **`user.md`** — 사용자 비즈니스 환경·관심사·협업 패턴 (초개인화)
4. **`memory.md`** — 단기 기억 저장소. 글자 수 차면 시스템이 스스로 요약·정리

### 핵심 기능

- **칸반 대시보드**: 한 줄 의도만 던지면 자동으로 업무를 쪼개 칸반 카드(Todo→In Progress→Done) 생성, 병렬 서브에이전트팀이 QA까지 원스톱 처리
- **프로액티브 기능**: 크론잡으로 먼저 트렌드 모니터링·인사이트 제안, 구글 캘린더/Gmail 연동 아침 브리핑 자동 전송
- **실무 개발 자율화**: GitHub 이슈 등록 시 밤새 도커 내에서 테스트·CI 실패 분석·수정 후 머지 가능한 PR 대기

### 인프라 구축 요약

1. 개인 메인 PC 대신 클라우드 VPS(호스팅어 우분투/도커 등)에 격리 환경 구축
2. LLM 라우팅: 구독형 API 또는 OpenAI Codex, Claude API 유연 스위칭
3. 디스코드 게이트웨이: 봇 애플리케이션 생성 + `Message Content Intent` 권한 부여, `Allowed User ID`로 무단 사용 방지
4. VS Code Remote-SSH로 `require_mention` 속성을 `false`로 바꾸면 매번 `@멘션` 없이 사용 가능

**마인드셋**: "어떻게 구현해줘" 수준을 넘어, 의도(Intent)를 명확히 전달하고 중간 결과물을 끊임없이 인간과 싱크(Human-in-the-loop)할 때 완성도가 올라간다.
