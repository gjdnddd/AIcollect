## 공통 규칙 (전 단계 적용)

### 컨펌 트리거
다음 경우 AI는 멈추고 컨펌받는다:
- 파일 신규 생성·삭제
- 2개 이상 파일 동시 수정
- 마스터가 명시하지 않은 라이브러리·도구·외부 서비스 도입
- 인프라 설정(GCP, OneDrive, API 키 등) 변경
- 작업 범위 확장 ("이것도 같이 고치면 좋겠다" 류)

### 단계 회귀 가능
어느 단계에서든 이전 단계의 결정에 문제가 발견되면, 강행하지 않고 해당 단계로 회귀한다.

> 코드 작성·디버깅·모델 선택·토큰 절약 등 작업 방법론은 **AI일반.md** 기본 규칙·3부 참조

## 0단계: 프로젝트 시작

**목적**: 작업 환경과 운영 도구를 미리 셋업한다.

### 폴더 구조
- 위치: `OneDrive/개발/<프로젝트명>/`
- 단일 폴더 구조. 하위 폴더로 단계별 분리하지 않는다.
- 프로젝트명: 한글·영문 모두 허용. 공백 대신 `_` 사용. 짧고 직관적으로.
  - 예: `TQQQ_VR계산기`, `쇼핑몰_최저가탐색`

### 맥락노트 (`맥락노트_<프로젝트명>.md`)
프로젝트 시작 시 생성. 전 단계에 걸쳐 1개 파일을 갱신한다.

**기록 내용:**
- 왜 이렇게 결정했나 (주요 의사결정과 이유)
- 자료는 어디 있는가 (참고 링크, 파일 위치)
- 제약사항 (환경·기술·시간·예산)
- 합의 내용 (마스터와 AI 사이 확정 사항)

**갱신 시점:**
- 단계 종료 시
- 주요 의사결정이 내려졌을 때
- 가정이 검증되거나 폐기되었을 때
- 외부 AI 검토 결과가 반영되었을 때

### 체크리스트 (`체크리스트_<프로젝트명>.md`)
프로젝트 시작 시 생성.

**기록 내용:** 완료 / 진행중 / 남은 작업 / 각 작업의 검증 상태

**갱신 시점:**
- 각 덩어리·작업이 완료될 때마다
- 검증이 완료될 때마다
- 새 작업이 추가되거나 변경될 때

### 0단계 종료 조건
- 프로젝트 폴더 생성 완료
- 맥락노트 초기 파일 생성 완료
- 체크리스트 초기 파일 생성 완료
- 마스터가 **"0단계 완료"** 명시적 컨펌

## 1단계: 구상

**목적**: 막연한 아이디어 → 구체적 요구사항  
**출력물**: `01_구상_<프로젝트명>.md`

### 규칙

- **AI 주도 인터뷰**: 마스터는 아이디어만 던진다. AI가 질문으로 구체화한다.
- **한 번에 1~3개 질문**: 관련 주제끼리 묶어서 묻는다. 한 번에 너무 많이 묻지 않는다.
- **선택지 제시**: 마스터가 결정하기 쉽도록 옵션(A/B/C) 형태로 제시한다. 단, 자유 답변이 더 적절한 경우는 예외.
- **인터뷰 항목은 AI가 판단**: 필수 질문 목록을 사전에 고정하지 않는다. 프로젝트 성격에 따라 AI가 무엇을 물어야 할지 판단한다.

### 1단계 종료 조건
요구사항 문서가 작성되고 마스터가 **"구상 완료"** 명시적 컨펌.

---

## 2단계: 설계

**목적**: "어떻게 만들지" 구조 결정  
**출력물**: `02_설계_<프로젝트명>.md`

### 규칙

- **환경 파악이 최우선**: 설계 시작 전 다음을 점검한다:
  - 실행 환경 (PC / 폰 / GCP / 브라우저 등)
  - 필요한 도구·계정의 보유 여부
  - API·외부 서비스의 실제 가용성
  - 마스터의 기존 인프라(OneDrive, GCP, 한투 API 등)와의 연결 가능성

- **환경 파악 실패 시 회귀**: 환경 제약으로 1단계 요구사항이 불가능하면 설계를 강행하지 않고 1단계로 회귀하여 요구사항을 조정한다.

- **설계 범위 한정**: 기술 스택 / 파일 구조 / 데이터 흐름 (입력→처리→출력). 화면 와이어프레임·함수 단위 분해 등 세부 설계는 구현 직전 미니 설계로 처리.

### 2단계 종료 조건
설계 문서가 작성되고 마스터가 **"설계 완료"** 명시적 컨펌.

---

## 3단계: 구현

**목적**: 설계대로 실제 작동하는 코드·시스템을 만든다.  
**실행 주체**: Claude Code (Sonnet) + 마스터 검수  
**출력물**: 코드·설정 파일 일체 + 체크리스트·맥락노트 갱신

### A. 진행 단위 규칙

- **한 덩어리 = AI가 안정적으로 처리 가능한 최대 단위**

- **덩어리 분할 기준**: 다음에 해당하면 분할한다:
  - 새 라이브러리·외부 서비스 도입 포함
  - 인프라 설정 변경 포함
  - 검증이 까다로운 로직 (자동매매·결제·외부 API 등)
  - 작성 분량이 처리 한계 초과

- **덩어리 단위 컨펌**: 매 덩어리 시작 전 AI는 마스터에게 제안한다 — 포함 작업 목록 / 한 번에 처리하는 이유 / 예상 결과물. 컨펌 후 진행.

- **덩어리 내부는 컨펌 없이 진행**: 단, 공통 컨펌 트리거에 해당하면 중간이라도 멈추고 컨펌.

### B. 작동 확인 규칙

- **AI 1차 검증 → 마스터 2차 검증**: 덩어리 완성 후 AI가 먼저 실행·검증 → 마스터에게 보고 → 마스터가 실사용 환경에서 2차 검증 → 둘 다 통과해야 다음 덩어리 진행.

### C. 오류 발생 시 규칙

- **동일·유사 오류 2회 → 다른 채팅창 권유**: 같은 오류 또는 유사 패턴 오류가 2회 반복되면 즉시 다른 채팅창에서 재질문을 권유한다.

- **다른 채팅창에서도 실패 → 다른 AI 권유**: ChatGPT·Gemini 등 다른 AI에게 문의를 권유한다.

- **외부 문의용 요약 자동 생성**: 무엇을 만들려고 하는지 / 현재 시도한 방법 / 발생한 오류 / 관련 코드.

### D. 외부 AI 검토 규칙

- **기능 1개 완성 시점에 외부 AI 검토**: 작성된 코드 / 의도·목적 / AI 자체 우려점·확신 없는 부분을 요약해 마스터에게 전달. 외부 AI 검토 이력은 맥락노트에 기록.

### E. 서브 채팅창 병렬 개발 규칙

- **의존성 분류**: 3단계 시작 시 선행 의존 작업(메인) / 독립 가능 작업(서브 병렬)으로 분류. 마스터 컨펌 후 진행.

- **서브 채팅창용 명령서**: 해당 구상·설계 결과 / 작업 범위 / 입출력 인터페이스 / 본 규칙 파일 일체.

- **서브 채팅창 모델**: Sonnet 사용 권장.

- **서브 결과 통합 시 메인 AI 검증**: 인터페이스 일치 / 규칙 준수 / 메인 코드와 충돌 없는지 검증.

- **메인 채팅창 = 진행 트래커**.

### 3단계 종료 조건
모든 덩어리가 완성·검증되고 마스터가 **"구현 완료"** 명시적 컨펌.

## 4단계: 배포·운영

**핵심 원칙**: **기존 운영 시스템에 영향 없을 것** — 4단계의 최우선 원칙.

### A. 배포 규칙

- **1회 컨펌 후 진행**: AI는 배포 전 점검 결과를 보고하고 마스터가 "배포" 컨펌하면 일괄 진행.

- **배포 전 필수 점검** (1번이 최우선):
  1. **기존 운영 시스템과 충돌 여부** ← 최우선
     - 동일 프로세스 중복 실행 방지
     - 동일 포트·리소스 충돌 없는지
     - 기존 데이터·설정 덮어쓰기 위험 없는지
  2. API 키·시크릿이 코드에 노출 안 됐는지
  3. 테스트 데이터·디버그 코드가 남아있지 않은지

### B. 모니터링

모니터링 방식은 프로젝트별로 결정. AI는 프로젝트 성격에 맞는 옵션을 제안하고 마스터가 선택한다.

### C. 배포 이력 기록 (맥락노트)
- 배포 일시 / 변경된 내용 요약 / 기존 시스템 충돌 점검 결과 / 배포 후 작동 확인 결과

### 4단계 종료 조건
- 배포 완료 + 기존·신규 시스템 정상 작동 확인
- 마스터가 **"배포·운영 시작"** 컨펌

---

## 5단계: 확장·수정

**핵심 원칙**: **이미 돌아가고 있는 것을 망가뜨리지 않는 것** — 5단계의 최우선 원칙.

### A. 시작 판단

- **단순 수정**: 기존 기능 일부 변경, 작은 버그·기능 추가 → 3단계 → 4단계만 거침
- **중대 확장**: 새 기능 모듈, 구조 변경, 다른 시스템 연동 → 1단계부터 재시작

### B. 회귀 방지

- **현재 작동 상태 스냅샷**: 수정 전 잘 작동하는 기능 목록 명시. 수정 후 이 목록이 그대로 작동하는지 확인.

- **수정 범위 엄수**: 수정 범위를 벗어나는 코드는 절대 건드리지 않는다. 개선이 필요한 부분은 별도 항목으로 보고만.

- **기존 안전장치 유지 확인**: 중복 실행 방지 로직 / 예외 처리 / 안전장치 (거래 한도, 호출 제한 등)

### C. 영향 범위 분석

수정 시작 전 영향을 받는 기능·파일 목록 분석. 마스터 컨펌 후 진행. 범위가 넓으면 분할.

### D. 운영 중단 최소화

24/7 운영 시스템 수정 시: 중단 필요 여부 / 무중단 가능 여부 / 중단 시점 협의. 재시작 시 4단계 점검 재수행, 특히 **중복 실행 방지** 확인 필수.

### E. 수정 이력 기록

**맥락노트 갱신:** 수정 이유 / 내용 요약 / 영향 범위 / 변경 전후 동작 차이 / 결정 과정

**체크리스트 갱신:** 수정 작업을 새 항목으로 추가하고 완료·검증 상태 추적.

### 5단계 종료 조건
- 수정·확장 완료 + 회귀 점검 통과
- 마스터가 **"확장·수정 완료"** 컨펌
