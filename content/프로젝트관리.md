# 프로젝트 관리 가이드

> AI와 협력하여 프로젝트를 시작·구현·배포·유지하는 단계별 규칙.
> 특정 AI 도구에 국한되지 않는 개인 개발 프로세스.

---

## 📋 전체 단계 구조

| 단계 | 이름 | 핵심 원칙 |
|---|---|---|
| 0단계 | 프로젝트 시작 | 폴더·맥락노트·체크리스트 셋업 |
| 1단계 | 구상 | AI 주도 인터뷰로 아이디어 구체화 |
| 2단계 | 설계 | 환경 파악 → 기술 스택 → 구조 결정 |
| 3단계 | 구현 | Claude Code (Sonnet) 주도 |
| 4단계 | 배포·운영 | 기존 시스템에 영향 없을 것 |
| 5단계 | 확장·수정 | 이미 돌아가는 것을 망가뜨리지 않을 것 |

---

## 0단계: 프로젝트 시작

### 폴더 구조
- 위치: `OneDrive/개발/<프로젝트명>/`
- 단일 폴더 구조. 하위 폴더로 단계별 분리하지 않는다.
- 프로젝트명: 공백 대신 `_` 사용. 짧고 직관적으로.

### 필수 생성 파일 (2종)

- `맥락노트_<프로젝트명>.md` — 왜 이렇게 결정했나 / 자료 위치 / 제약사항 / 합의 내용
- `체크리스트_<프로젝트명>.md` — 완료 / 진행중 / 남은 작업 / 검증 상태

### 공통 규칙 (전 단계 적용)

- **컨펌 트리거**: 파일 생성·삭제 / 2개+ 파일 동시 수정 / 미지정 라이브러리·외부 서비스 도입 / 인프라 설정 변경 / 작업 범위 확장
- **닻 회피**: 사용자가 예시로 든 도구는 참고. AI는 더 적합한 대안 있으면 비교 제시.
- **가정 금지**: "아마 될 것이다"로 진행하지 않는다.
- **단순성 우선**: 같은 결과면 더 단순한 구조 선택.
- **기술 용어 최소화**: 비유·결과·시나리오 중심으로 설명.
- **단계 회귀 가능**: 어느 단계에서든 이전 단계에 문제 발견 시 회귀.

---

## 1단계: 구상

**목적**: 막연한 아이디어 → 구체적 요구사항  
**방식**: AI가 인터뷰 주도. 한 번에 1~3개 질문.  
**출력물**: `01_구상_<프로젝트명>.md`  
**종료**: 사용자 "구상 완료" 컨펌

---

## 2단계: 설계

**목적**: "어떻게 만들지" 구조 결정  
**순서**: 환경 파악 → 기술 스택 → 파일 구조 → 데이터 흐름  
**출력물**: `02_설계_<프로젝트명>.md`  
**원칙**: 가정 위에 설계 쌓지 않기. 불가능 확인되면 1단계로 회귀.  
**종료**: 사용자 "설계 완료" 컨펌

---

## 3단계: 구현

**실행 주체**: Claude Code (Sonnet) + 사용자 검수  
**덩어리 크기**: AI가 판단 → 시작 전 작업 목록 제안 → 컨펌 → 진행  
**검증**: AI 1차 검증 → 사용자 2차 검증  
**동일 오류 2회**: 다른 채팅창 권유 → 다른 AI 권유  
**종료**: 사용자 "구현 완료" 컨펌

---

## 4단계: 배포·운영

**핵심 원칙**: **기존 운영 시스템에 영향 없을 것**

### 배포 전 필수 점검

1. **기존 시스템 충돌 여부** (최우선) — 동일 프로세스·포트·리소스 충돌, 데이터 덮어쓰기 위험
2. API 키·시크릿 코드 노출 여부
3. 테스트 데이터·디버그 코드 잔류 여부

→ 점검 결과 보고 → 사용자 "배포" 컨펌 → 일괄 진행

### 배포 이력 기록 (맥락노트)
- 배포 일시 / 변경 내용 요약 / 충돌 점검 결과 / 작동 확인 결과

---

## 5단계: 확장·수정

**핵심 원칙**: **이미 돌아가고 있는 것을 망가뜨리지 않는 것**

### 수정 요청 분류 (먼저 판단)

- **단순 수정**: 3단계 → 4단계만 거침
- **중대 확장**: 1단계부터 재시작 (사실상 새 프로젝트)

### 회귀 방지

- 수정 전 **현재 작동 기능 목록** 명시 → 수정 후 동일 작동 확인
- 수정 범위 밖 코드 절대 건드리지 않는다
- 기존 안전장치 유지 확인: 중복 실행 방지 / 예외 처리 / 거래 한도·호출 제한

### 영향 범위 분석

- 수정 전 영향 받는 기능·파일 목록 분석 → 사용자 보고 → 컨펌 → 진행
- 영향 범위가 넓으면 여러 덩어리로 분할

---

## 핵심 규칙 요약 (세션 시작 시 붙여넣기)

```
마스터는 요구사항 제공자·검수자. AI는 설계자·구현자.
기술 용어 대신 비유·결과 중심으로 설명.
응답은 짧게. 불필요한 반복·인사 제거.
모델: 설계·의사결정 → Opus / 구현·반복 → Sonnet

컨펌 트리거: 파일 생성·삭제 / 2개+ 파일 동시 수정 / 미지정 라이브러리 도입 / 인프라 변경 / 작업 범위 확장
```
